# Foundational Chain — “How Did This Get Here?”

When a future maintainer asks where a behavior, convention, or architecture came from, trace it in this order:

1. **Current v.002+ forward state** — `reference/ssot/`, current `docs/v00N/`, active source/tests.
2. **v.001 canonical instantiation** — `docs/v001/` and `00_V001_START_HERE.md`.
3. **Seed 1 reconciliation** — `docs/SEED_*`, root Seed-era manifests/evidence, current-runtime docs from that chapter.
4. **Historical XtraType canon** — `reference/canon/XtraType_Canon_v1.0_candidate/` for v2.3 baseline/audit/provenance.
5. **Selected PortaShape target** — `reference/specs/XtraType_PortaShape_Companion_v0.1/` for the chosen future host/plugin/interoperability architecture.
6. **Preserved source snapshots / evidence** — exact older bytes and test evidence when wording alone is insufficient.

A forward change should be able to explain which layer it extends, which invariant it preserves, and which explicit decision authorizes any departure. If the chain cannot explain a major subsystem, create the missing decision/provenance record before the omission becomes folklore.
