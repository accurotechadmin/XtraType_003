# XtraType v.001 — Foundational Decisions and Open Boundaries

This is a compact decision register for facts that future sessions should not repeatedly rediscover or accidentally reopen without cause.

## Settled at v.001

**FD-001 — XtraType remains XtraType.** PortaShape wraps/hosts shared capabilities and plugins; it does not erase XtraType's first-party contextual identity.

**FD-002 — The predecessor baseline is immutable.** The sealed 260 files are perpetual legacy authority and are never retroactively rewritten.

**FD-003 — Forward canonical naming begins at v.001.** Historical `2.5.0` identifiers remain frozen evidence.

**FD-004 — Local annotation durability precedes optional remote success.** Network failure must not silently erase a locally committed note.

**FD-005 — Compatibility-critical identities are protected.** `portashape-xtratype` IndexedDB v1, its current stores, Annotation v2, Snapshot v1, and target-key semantics require explicit migration to change.

**FD-006 — Typed target identity and applicability are separate concepts.** Exact keys are not interchangeable with “matches current context.”

**FD-007 — Custom schemas are inert bounded data.** They are not plugins or executable schemas.

**FD-008 — Page-owned overlays are not secrecy boundaries.** Do not place secrets in quick-bar/YouTube DOM under a false assumption of extension-only visibility.

**FD-009 — Imported artifacts do not bring authority.** Grants, credentials, sessions, and local observation buffers are not transferred merely because data/package metadata says they exist elsewhere.

**FD-010 — Privileged extension code is reviewed host code.** Arbitrary downloaded/evaluated code must not gain privileged package authority.

**FD-011 — External-effect truth includes unknown outcome.** Unknown must be reconciled before retry where duplication is possible.

**FD-012 — Accounts are bounded implementation, not public-platform certification.** The current PHP/JSON auth/messaging layer does not prove hardened internet-scale service behavior.

**FD-013 — Invitation rollout has two limits.** Code enforces normal per-user one-per-fixed-EST-day cadence; a separate confidential owner-held total capacity ceiling governs current rollout.

**FD-014 — Community extensibility is intentional.** The architecture must support scripts/modules/plugins while assuming untrusted/buggy artifacts exist and containing their authority.

**FD-015 — History is preserved by addition, not rewriting.** Corrections are successor documents/decisions.

## Open but bounded decisions

**OB-001 — Technical mapping of v.00N into Chrome/npm/server version fields.** Decide before first post-v.001 code release; do not rewrite predecessor fields.

**OB-002 — Production service plane.** Identity/sync/conflict/storage/hosting architecture beyond the bounded current service needs explicit design and threat model.

**OB-003 — Global invitation-cap enforcement mechanism.** Operational cap exists; repository-level enforcement is not established in v.001.

**OB-004 — Complete backup/restore.** Metadata export and snapshot upload are not a full binary/account/social restore system.

**OB-005 — Distributed deletion/conflict semantics.** Tombstones, ownership reconciliation, multi-device editing, and remote revocation need design.

**OB-006 — PortaShape runtime deployment split.** Initial target assumes embedded/transport-neutral host boundary; future process/daemon/cloud split requires ADR while preserving contracts.

**OB-007 — Privileged package distribution/review model details.** Companion chooses reviewed privileged packages; operational signing/catalog/update governance still needs implementation decisions.

**OB-008 — Public social safety model.** Blocking/reporting/moderation/retention/export/privacy controls become necessary as cohorts grow.

**OB-009 — E2E message encryption.** Not implemented or promised by v.001; any later addition requires explicit key/recovery/multi-device design.

**OB-010 — Native/mobile capability model.** Clients may share contracts but must not claim extension-only capabilities they cannot execute.
