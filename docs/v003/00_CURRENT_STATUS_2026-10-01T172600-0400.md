## Corrective client change

Ctrl+Q uses Chrome's reserved Manifest V3 `_execute_action` command. The extension worker enables `setPanelBehavior({openPanelOnActionClick:true})`, so Chrome routes the keyboard shortcut through the same native extension-action path as the toolbar button.

The failed v.003 manual branch has been removed: there is no `toggle-xtratype` command listener, no side-panel context polling with `chrome.runtime.getContexts()`, and no keyboard-specific `chrome.sidePanel.close()` call. Programmatic side-panel opening remains only for distinct flows such as context-menu and omnibox entry.

The extension minimum is Chrome 116; Chrome 141 is no longer required for the shortcut because XtraType no longer owns an explicit close call.

## Unchanged contracts

- local-first personal annotation use remains available without the server;
- IndexedDB/record/anchor identities are unchanged;
- server/account/messaging maturity claims are unchanged;
- PortaShape remains selected target architecture rather than blanket implementation truth.

## Verification

The focused manifest/UI regression test asserts `_execute_action`, the cross-platform Ctrl+Q suggestions, retained native `openPanelOnActionClick` behavior, and the absence of the orphan manual command/context/close path. Native Chrome acceptance is still required because shortcut assignment can be affected by browser/user shortcut settings.

## Installation / update

At `chrome://extensions`, reload the unpacked XtraType extension after pulling v.003. Then open `chrome://extensions/shortcuts`, verify XtraType's action shortcut is Ctrl+Q (assign it manually if Chrome did not accept the suggestion), and test Ctrl+Q plus the toolbar button on a normal page.
