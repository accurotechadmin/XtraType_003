## Executive status

XtraType v.002 preserves the v.001 working application code while formalizing the documentation/decision/reference system that will govern future growth. The Chrome extension is designated **tested and working for personal client-side, non-server-dependent use**. Server-side identity, invitation, messaging, synchronization, deployment, security, recovery, and scaling work is **under heavy development and testing** and should not be represented as a finished public service platform.

## Personal client-side use

A user who wants the personal local extension can load it directly:

1. open `chrome://extensions` in Chrome;
2. enable **Developer mode**;
3. click **Load unpacked**;
4. select the repository's `/ext` folder.

The current client-side baseline includes local contextual annotation workflows, built-in URL/Time/YouTube/GPS anchors, custom bounded anchor schemas, tab/URL/SPA context refresh, Ctrl+Q side-panel action, `xt` omnibox compose handoff, seven-day young/tree/badge state with explicit Mark all as old, capture/snapshot/timeline/compare, and optional server synchronization hooks that do not replace local-first authoring.

## Server-side status

Server code exists for contextual APIs plus registration/login, seed administration, single-use invitations, admin account/invite controls, contacts, DMs, and access-controlled XT Group Chats. This is an active-development service layer. Production deployment hardening, generalized public identity/recovery, broad abuse resistance, full cross-device sync, distributed conflict resolution, E2E messaging, migration/recovery guarantees, and public-scale acceptance remain open work.

The owner-established finite invitation ceiling remains confidential and is not represented by a public repository constant. The existing per-user invitation cadence is a separate implementation rule.

## PortaShape ecosystem status

PortaShape remains the selected wraparound framework direction: plugin/package lifecycle, capability grants, operation routing, portable records/provenance/representations, UI contributions, local data transportation, Script Studio, Stay D.R.Y., Universal Publisher/Bridges, external connector packages, and shared clients. The selected Companion v0.1 is foundational target truth; broad runtime implementation is not yet complete.
